# Audit of a third-party DA2 2710EX01 (issue bkerler/mtkclient#409) with our scripts

Date: 2026-10-25. Artifact: `DA2_extracted.zip` from the comment
`#issuecomment-6394994089` (the comment `6382463089` it referred to contains no
attachment).

Tool: `docs/notes/da2_static_audit.py` (ARM32, file offset 0 == VA
`0x40000000`, movw/movt + literal-pool xref, capstone). The reference for
comparison is our `docs/notes/rmx3630-da2/da2_oplus.bin` (200EX01) and
`MTK_AllInOne_DA.bin` (generic).

```
$ python3 docs/notes/da2_static_audit.py DA2_extracted.bin
size   358160
sha256 f95f2b82c684115a0fd4bf50f3286ebcb357721a19134d56515d534e209dde47
```

The hash and size match the values stated by Alexander. Our `da2_oplus.bin`
lives inside `DA_BR.bin` at offset `428728`, so we are comparing the correct
pair — "same product, different build".

## Correction #1: the `0xc0010006` check is not new

Comment #8 says "the fork changed both the request (clamp) and the callback
(rejects a packet larger than the request)". The clamp really is new. The
rejection, however, is **the very same code in both builds**:

```
2710EX01 @0x4002aa88..                    200EX01 @0x4002a994..
movw r0,#0xeeef / movt r0,#0xfeee         movw r0,#0xeeef / movt r0,#0xfeee
cmp  r1,r0                                cmp  r1,r0
bne  -> 0xc0010005                        bne  -> 0xc0010005
ldr  r0,[r5]      ; capacity              ldr  r0,[r5]
ldr  r1,[sp,#0x48]; envelope payload_len   ldr  r1,[sp,#0x48]
cmp  r0,r1                                 cmp  r0,r1
bhs  -> OK (recv payload_len)              bhs  -> OK (recv payload_len)
movw r0,#5 / movt r0,#0xc001               movw r0,#5 / movt r0,#0xc001
add  r4,r0,#1     ; 0xc0010006             add  r4,r0,#1     ; 0xc0010006
```

`0xc0010006` is built as `0xc0010005 + 1`; in mtkclient this is
`"Protocol buffer overflow"` (`mtkclient/Library/error.py:557`). In 200EX01 the
check simply **never fires**, because it is passed
`capacity = packet_len = 0x2000` instead of the real remainder `0x13FC`. In
other words, the primitive is closed by the clamp; the callback was already
the same.

## Correction #2: "no string" ≠ "no command"

Comment #15 concludes "OPLUS completely removed the entry point,
`CUSTOMRPMBI/BK` do not exist, this is dead code" on the basis of missing
strings. That is **not a valid criterion**: our own 200EX01
(`da2_oplus.bin`, sha `fd3a5038…`) has none of those strings either —

```
$ python3 docs/notes/da2_static_audit.py docs/notes/rmx3630-da2/da2_oplus.bin
strings.customrpmbi: []   strings.customrpmbk: []   strings.customrpmbr: []
```

— and yet on that very DA2 the commands **work**:

```
/home/musin/planb_recon2.log
[*] CUSTOMRPMBI: status=0, returned key 75a41c1a…7a97
[*] CUSTOMRPMBK: key set + echo ok (75a41c1a…7a97)
```

The command registrar (`0x40001a6c` in 200EX01) does not contain
`CUSTOMRPMB*` at all; the full `CMD:*` list is identical in both binaries
(31 names: `CMD:REBOOT`, `CMD:EMMC-CONTROL`, `CMD:OPLUS-*`, …), and
`CUSTOMRPMBI` is not in it in either. So on 200EX01 these commands are not
dispatched through a string table (either the name is assembled/compared
differently, or the handler lives in another layer). Conclusion: **the absence
of the strings on 2710 proves nothing**; before pivoting to DA1, check the
handler itself, not the strings.

Practical device check: send `CMD:CUSTOMRPMBI` to 2710EX01 and see whether
`OK`/32 bytes or `ERR!UNSUPPORTED` comes back. That is one command and one log.

## What remains unverified

* Heap geometry (comment `6382463089`) cannot be checked statically; it needs
  a UART free-list dump. Our conclusion from `re-heapbait-stabilize.md`
  (the victim is the cached S1, freed at `0x4002d428`/`+0x24`) does not depend
  on the build and still stands.
* The exact point where the `[r8]` callback of `fp_read_host_file` is tied to
  the envelope check `0x4002aa28`: the ops table `0x40054a58` is zero in the
  file (it is initialised at runtime).
* DA1 (as in Alexander's work) was not audited.

## Reproduction

```
python3 docs/notes/da2_static_audit.py <DA2.bin>        # JSON to stdout
```

The script prints: identity, presence/liveness of the tripwire, `clamped` for
`fp_read_host_file` with the instruction quotes, the escape-helper bound, the
`CMD:*` list, and the addresses of `rpmb_hmac`/staging/wipe.
